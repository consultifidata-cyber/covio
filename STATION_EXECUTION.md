# Machine Station — who runs what on the board

The station shares one ESP32-S3 with the pulse counter that Wire Line 1's production data depends on. This file names every piece of work, who owns it, and what each blocking operation can and cannot hold up. It is the S6 §5 review, written down. The proofs are in `test/native_cpp/` (named per row).

## Owners

| Owner                                                                                 | Runs                                                                                                                                                                                                                    | Writes                                                                                                              |
| ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **PCNT hardware**                                                                     | counts every rising edge on DI1 into a 16-bit register, always, with no software involved                                                                                                                               | the register                                                                                                        |
| **The loop** (`loop()`, Arduino task, core 1)                                         | telemetry row each second; draining the station's events into rows; checkpointing; ONE network transaction per pass (push, else K-factor config, else station config, else OTA); the watchdog feed; the output failsafe | **the only writer** of the durable queue, of `seq`, of the totalizer checkpoint, and of the station config on flash |
| **The station task** (`station_runtime.h`, FreeRTOS, core 1, priority 2, every 20 ms) | reader poll; one logic tick per uptime second (a tap takes the next second's tick at once); the outputs through the governor; the beeper                                                                                | its own RAM state; the in-memory event queue (160); the expander's output register                                  |
| **The console** (`provision.h`, in the loop)                                          | operator commands                                                                                                                                                                                                       | NVS settings; `station tap` into the console reader's one-slot mailbox                                              |

The station task **reads** the PCNT register to learn whether the machine moved (`pcnt_get_counter_value`) and never clears it. `test_station_corun` counts every clear and asserts none came from the station.

## The two evidence streams

- **Measurement and station events share ONE durable queue and ONE seq** (MC-004). A station event can never block a measurement row: the server acknowledges a station row it cannot use (it advances the watermark), and the station's after-push work cannot change the ack. A station row the full flash refuses **gives its seq back** (the server stops at a hole). No station row is drained before this boot's first telemetry row, so the one seq a power cut can reuse always goes to telemetry, which the server may drop harmlessly. Proven: `test_station_corun` scenarios A–G.
- **Capacity:** the 3.5 MB flash queue holds ~98,000 rows, **about 27 hours of 1 Hz telemetry** offline; station rows add a few hundred a day. The in-memory station queue holds 160 events, every event an 80 s loop stall can produce with a card tapped every second. Losses are counted and reported (`dropped` in the envelope; Health shows it): RAM queue full, or a full flash refusing a row, or a power cut taking the RAM queue.
- **Pre-existing, not the station's:** a TELEMETRY row the full flash refuses still checkpoints its seq, and the server waits at that hole until `reset_ack`. covio-fw #17 fixes it (counting path: bench + second signature). And the PCNT headroom: after a checkpoint the register can hold 29,999 undrained counts, so a full 80 s stall is exact up to **34 Hz sustained** (Wire Line 1 runs ~6 Hz).

## The outputs

- **Off first:** the first line of `setup()` writes the expander's outputs OFF (`Pca9554Outputs::earlyOff`), because the TCA9554 keeps its state through a CPU reset.
- **Three fences on the sounder:** the logic (≤ 5 announcements of 4 s, ≤ 60 s per stop, then never again for that stop, online or not: `test_station_alerts`); the governor (≤ 10 s a burst, a 1 s rest, ≤ 60 s in ten minutes, everything off if the task stops refreshing for 3 s: `test_station_io`); and the **physical fence**, a self-ending sounder or a time-limit relay, chosen on the bench (B31). Only the last survives a CPU that is held in reset, which is why it is required.
